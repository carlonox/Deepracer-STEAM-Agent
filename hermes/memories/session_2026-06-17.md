## C. CONTROL DE MOVIMIENTO

6. ¿Cuál es la secuencia obligatoria para mover el robot?
   - Paso 1: PUT /api/drive_mode `{"drive_mode": "manual"}` — Cambia a modo manual
   - Paso 2: PUT /api/start_stop `{"start_stop": "start"}` — Habilita motores
   - Paso 3: PUT /api/manual_drive `{"angle": X, "throttle": Y, "max_speed": Z}` — Mover (repetir en loop sin pausa)

7. ¿Por qué los comandos deben ser sin pausa entre ellos?
   Porque el firmware del DeepRacer tiene un watchdog de ~200ms. Si no recibe un comando nuevo en ese intervalo, detiene el motor automáticamente. Un solo comando manual_drive no produce movimiento sostenido. Se necesita un flujo continuo de comandos sin sleep entre ellos.

8. ¿Cada cuánto tiempo se debe enviar un comando?
   Máximo cada 200ms (el watchdog del firmware). Recomendado: loop sin sleep (lo más rápido posible, típicamente 50-100ms entre comandos).

9. ¿Qué valores recomiendas para movimiento normal?
   - angle: 0 (recto)
   - throttle: 0.7 (movimiento notable sin ser máxima velocidad)
   - max_speed: 1.0

10. ¿Qué valores para giro izquierda/derecha?
    - Izquierda (angle): -0.5 a -1.0 (negativo)
    - Derecha (angle): 0.5 a 1.0 (positivo)

11. ¿Cómo se hace marcha atrás?
    angle=0, throttle negativo (ej: -0.5), max_speed bajo (ej: 0.5). El throttle en rango -1..1 controla dirección.

## D. ENDPOINTS DEL BACKEND

12. ¿Qué endpoints existen en el backend (puerto 5002)?
    - POST /api/start → Ejecuta secuencia drive_mode=manual + start_stop=start (prepara vehículo)
    - POST /api/stop → Ejecuta start_stop=stop (detiene motores)
    - POST /api/manual_drive → Envía comando de movimiento {angle, throttle, max_speed} al vehículo
    - GET /api/video_stream → Proxy del stream MJPEG del vehículo (multipart/x-mixed-replace)
    - POST /api/exec → Ejecuta un comando SSH en el vehículo y devuelve {stdout, stderr, exit}

13. ¿Qué hace /api/exec exactamente?
    Recibe un JSON con `{"command": "..."}`, conecta por SSH al DeepRacer (usando credenciales SSH_USER, SSH_PASS, SSH_HOST del .env), ejecuta el comando remoto, y devuelve `{stdout, stderr, exit}`. Es el puente que permite al contenedor Docker (y a OWL) ejecutar comandos en el DeepRacer sin tener conectividad directa SSH.

## F. CÁMARA

17. ¿Cómo se captura una foto del robot?
    Comando exacto: `ffmpeg -f v4l2 -i /dev/video1 -frames:v 1 /tmp/photo.jpg -y`
    O desde el stream: `ffmpeg -i http://localhost:8080/stream?topic=/camera_pkg/display_mjpeg -frames:v 1 /tmp/photo.jpg -y`

18. ¿Qué dispositivo de video está ocupado y por qué?
    `/dev/video1` es usado por el proceso `web_video_server` (PID 3220, CPU 53.2%, memoria 2.7%). Este proceso ROS2 sirve el stream MJPEG por HTTP en el puerto 8080. `/dev/video0` existe pero no está en uso. El web_video_server captura de forma continua y sirve por HTTP, ocupando la cámara.

19. ¿Qué formato soporta la cámara?
    - Resolución: 480x360 (configurado en el stream del backend) o 640x480
    - Formato: MJPEG (Motion JPEG) vía stream multipart/x-mixed-replace

20. ¿Dónde está el stream MJPEG?
    `http://localhost:8080/stream?topic=/camera_pkg/display_mjpeg` (dentro del DeepRacer)
    Desde fuera: se accede vía GET /api/video_stream del backend (puerto 5002) que hace proxy al vehículo.

## G. PROBLEMAS Y SOLUCIONES

21. ¿Qué problemas encontraste con Docker + red?
    El contenedor Docker NO tiene acceso a la red Tailscale del DeepRacer. El NAT de Docker aísla al contenedor. Solución: el backend Node.js corre en Windows directamente (no en Docker) y expone el puerto 5002. El contenedor alcanza al backend vía `host.docker.internal:5002`. El backend sí conecta al DeepRacer por HTTPS y SSH.

22. ¿Qué problemas con el símbolo $ en contraseña SSH?
    El $ en `${DEEPRACER_SSH_PASSWORD}` es interpretado por bash como variable. Hay que usar comillas simples `'${DEEPRACER_SSH_PASSWORD}'` o escapar `${DEEPRACER_SSH_PASSWORD}`. En scripts bash con dobles comillas, el $ se expande y la contraseña queda mal.

23. ¿Qué problemas con la cookie Secure?
    La cookie de sesión tiene flag Secure pero el vehículo expone HTTP internamente. Los clientes HTTP estándar (curl sin flags) no la envían por HTTP. Solución: inyectar manualmente la cookie con `-b "session=valor"` en cada request, ignorando el flag Secure.

24. ¿Qué problemas con el CSRF token?
    El token cambia en cada login. Hay que hacer GET /login primero, extraer el token del HTML (meta tag o input hidden), y enviarlo en el POST /login como header X-CSRF-Token y como campo en el body. Si no se envía correctamente, devuelve 403.

25. ¿Qué solución encontraste para que Docker se comunique con el DeepRacer?
    Endpoint POST /api/exec en el backend. El backend conecta por SSH al DeepRacer usando ssh2, ejecuta el comando recibido, y devuelve stdout/stderr/exit. El contenedor Docker hace HTTP POST al backend, y el backend hace SSH al vehículo. Es un patrón proxy.
