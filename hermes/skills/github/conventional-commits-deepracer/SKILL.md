# Conventional Commits — Convención del repo Deepracer-STEAM-Agent

> **Regla dura:** todos los commits de este repositorio (sin excepción) deben
> seguir Conventional Commits 1.0.0: **type obligatorio, descripción
> imperativa, sin emojis, sin atribuciones automáticas.** El historial fue
> normalizado con este estándar (2026-09-05); no lo degrademos de nuevo.

## Cuándo activar esta skill

- Antes de CUALQUIER `git commit` o `git push` (agente del DeepRacer incluido)
- Cuando se revisa un mensaje de commit existente
- Cuando un colaborador hace push sin respetar el formato

## Formato obligatorio

```
<type>(<scope>): <descripción en imperativo>

<cuerpo opcional: el POR QUÉ>
```

### Tipos permitidos

| Type | SemVer | Cuándo |
|---|---|---|
| `feat` | MINOR | Nueva funcionalidad visible |
| `fix` | PATCH | Corrección de bug |
| `docs` | — | Solo documentación |
| `style` | — | Formato sin cambio de lógica |
| `refactor` | — | Reescritura sin bug ni feature |
| `perf` | PATCH/MINOR | Mejora de rendimiento |
| `test` | — | Añadir/corregir tests |
| `build` | varía | Build, dependencias, empaquetado |
| `ci` | — | CI/CD |
| `chore` | — | Mantenimiento que no toca src/test |
| `revert` | varía | Revertir commit |

### Reglas estrictas

1. **Type SIEMPRE en minúsculas** + `:` + espacio. `feat:`, `fix:`, `docs:` — nunca `FEAT:` ni `feature:`.
2. **Descripción en imperativo**: "add", "fix", "remove" — no "added", "fixed".
3. **Sin punto final** en la descripción.
4. **≤ 72 caracteres** en la línea de asunto.
5. **Sin emojis** pegados al type (`feat: 🚀` → NO).
6. **Sin atribuciones automáticas**: no `Co-authored-by`, no "Generated by", no "🤖".
7. **Commits atómicos**: un propósito lógico por commit. Si el diff mezcla feature+refactor+docs → dividir.
8. **Scope opcional** en minúsculas, sustantivo corto: `feat(robot):`, `fix(simulator):`, `docs(plans):`.
9. **El detalle va en el CUERPO**, nunca en la primera línea (el historial ya lo padeció).

## Scopes recomendados para este repo

- `robot` — control físico del DeepRacer (drive, servos, watchdog)
- `backend` — apps/backend (Node, API :5002)
- `frontend` — apps/frontend (React)
- `simulator` — apps/simulator (mock)
- `navigation` — apps/navigation (ArUco, controlcamara)
- `rag` — apps/rag (conocimiento del aula)
- `voice` — STT/TTS
- `firmware` — ESP32/firmware (histórico)
- `hermes` — config/skills/SOUL del agente
- `ci` — workflows de GitHub Actions
- `security` — gitleaks, secretos, credenciales
- `docs` — documentación
- `plans` — planes y visión

## Ejemplos válidos

```
feat(simulator): add DeepRacer API mock for robot-free development
fix(ci): install test dependencies before running pytest
docs(plans): add agent evolution master plan
chore(security): purge leaked credentials from history
feat(robot): add drive tests
```

## Ejemplos inválidos (rechazar)

| Recibido | Problema | Corrección |
|---|---|---|
| `Update login.ts` | Sin type | `fix(auth): corregir validación de login` |
| `feat: Added new endpoint.` | Pasado + punto | `feat(api): add user endpoint` |
| `fix: solving camera stream problem` | "solving" no es imperativo | `fix(camera): resolve video stream problem` |
| `feat: Add .env to .gitignore` | "Add" mayúscula + type mal | `chore: add .env to .gitignore` |
| `docs: mejora README... - item1... item2...` (todo en el asunto) | Asunto > 72 chars | Asunto corto + detalle en el cuerpo |
| `wip` / `asd` / `cambios` | Vago | Describir el cambio real |

## Flujo obligatorio antes de commitear

1. **Analizar**: `git status` + `git diff --stat` (nunca `git add -A` ciego).
2. **Verificar staging**: `git diff --cached --stat` — solo los archivos del propósito.
3. **Verificar secretos**: que ningún archivo stageado tenga credenciales (gitleaks si está; sino grep de `ghp_|sk-|tskey|token=|password=`).
4. **Commit**: `type(scope): descripción` + cuerpo si hace falta.
5. **Push**: verificar que los workflows CI están en verde antes de pedir merge (si el repo tiene branch protection, los PRs requieren CI verde).

## Archivos que NUNCA van a un commit

- `.env`, `*.env`, `*.env.*` (solo `.env.example`/`.env.template`)
- `hermes/config.yaml` real, `auth.json`, claves, tokens
- `hermes/state.db*`, `sessions/`, `logs/`, `caches/`
- `apps/simulator/certs/` (certificados autofirmados generados)
- Cualquier artefacto con credenciales del robot (password.txt, token.txt)
